## Дополнительное задание

`ChainedHashTable` хранит пары `IssueId → ProjectTask` в массиве корзин.
В каждой корзине находится односвязная цепочка узлов. Индекс корзины вычисляется
по `hashCode` ключа через `Math.floorMod`, а нужный узел в цепочке ищется через
`equals`. Поэтому разные ключи с одинаковым хешем сохраняют отдельные значения.

Конструктор `new ChainedHashTable()` создаёт 16 корзин; например,
`new ChainedHashTable(4)` создаёт четыре. Количество корзин должно быть положительным
и не меняется при добавлении элементов. При длинных цепочках операции замедляются.
Готовые коллекции и дженерики внутри таблицы не используются.

Методы `put`, `get`, `remove`, `containsKey` и `size` соответствуют операциям
`IssueRegistry`. `put` возвращает предыдущее значение, `remove` — удалённое;
если записи не было, они возвращают `null`. Повторная вставка равного ключа
заменяет значение без увеличения размера. Ключи и значения могут быть `null`;
чтобы отличить отсутствующую запись от записи со значением `null`, используйте
`containsKey`. Обязательный `IssueRegistry` по-прежнему использует `HashMap`.

Тесты дополнительного задания находятся в `ChainedHashTableTest` и запускаются
общей командой `./mvnw -pl lab04 test` из корня репозитория.
